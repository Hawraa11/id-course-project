# Reflection

I used Cascade's AI assistant throughout this project to implement two features on an existing Task Tracker application. The AI tools I used included code inspection (read_file, list_dir), code editing (edit, multi_edit), test execution (bash with pytest), and file creation (write_to_file). The AI systematically followed the requested workflow: inspect first, plan second, then implement.

One moment where AI significantly helped was during the initial codebase inspection. The AI read all relevant files (models.py, main.py, storage.py, index.html, test_tasks.py) and accurately identified the existing architecture patterns. This allowed me to understand how to extend the filtering logic in storage.py without breaking the existing structure. The AI's suggestion to compute overdue status in the backend (rather than frontend) was particularly valuable because it maintained consistency with the existing architecture where all filtering logic already lived in the storage layer.

One moment where AI slowed me down was when I responded with a weak "continue" prompt instead of providing explicit requirements. The AI had asked three clarification questions about date format, overdue logic for completed tasks, and assignee filter case sensitivity. By not specifying these requirements, I relied on the AI to make architectural decisions. While the defaults it chose were reasonable, this could have led to implementation that didn't match my actual needs if the defaults had been different. A stronger prompt would have explicitly stated my requirements upfront.

One place where reviewing AI output improved the final implementation was during the frontend filter bar implementation. The AI initially set the board state to 'empty' when no tasks matched filters, which would have hidden the Kanban columns. I reviewed this and realized the requirement was to keep columns visible with an empty state message. The AI corrected this by changing the logic to always render columns with "No tasks" messages when empty, rather than hiding the board structure entirely. This review ensured the UI matched the specification.

Through this process, I learned that responsible AI-assisted development requires clear, specific prompts and active review of AI suggestions. The AI is a powerful tool for implementation, but the human must provide direction and verify architectural decisions align with requirements.
